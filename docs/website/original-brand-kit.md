# Original — official GFA / RecoveryOS brand kit

Approved direction: September 26, 2026, by the organization in the website preview review.

Original extends the approved GFA website preview across the shared RecoveryOS interface. The original logo is preserved. Its teal (#5AB2B4) and graphite (#4E4F50) anchor the identity. Supporting colors are deep teal actions (#24676A), charcoal (#0B1D20), warm white (#F6F8F7), and white. These supporting colors are accessible interface adaptations, not extracted logo colors.

Georgia provides the editorial display character on page titles; existing sans-serif type remains on controls, navigation, forms and body text. No additional font payload or decorative motion is introduced. Safety/status colors retain their established meanings.

## Selection and scope

- Original is the default when no valid theme is saved. The legacy GFA preference also maps to Original.
- Theme choices: Original, Hearth, Cosmic. Appearance choices remain Match device, Light, Dark. Cosmic retains its dark field.
- Existing explicit Hearth/Cosmic preferences are preserved. Preferences remain local to the device/browser origin, not account-synchronized.
- The shared token layer applies to participant, residence, staff, coach, navigator and administrator surfaces. Existing role labels and navigation remain intact.
- Desktop and mobile shell controls offer the same choices. Pre-paint resolution prevents a purple flash on first visit.
- The static GFA public preview remains its curated cinematic presentation; functional application pages use Original's shared colors and display typography.

## Validation and boundaries

Contrast gate reads Original color tokens from the shipped CSS; checks light/dark text, actions, selected states and focus rings. Appearance unit tests cover default selection, saved preferences, migration, switching and bootstrap/runtime agreement. Production build checked. Staging deployment and browser verification are recorded with the release; this document does not claim full WCAG certification or every authenticated workflow tested.

No backend, identity, intake, clinical/safety logic, or account data changes. Production rollout remains a separate deployment from the staging preview.
